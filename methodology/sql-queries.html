1Acquire Lead Connection Data from City API

The City of Regina publishes lead service connection locations via an ArcGIS REST API. This is the authoritative source for current lead connection counts.

1.1 Get Total Count

Query API for total connection count Shell 
curl "https://gis.regina.ca/arcgis/rest/services/OpenData/LeadConnectionAreas/MapServer/0/query?where=1%3D1&returnCountOnly=true&f=json"
Result (April 6, 2026): {"count": 2743}

1.2 Download All Features as GeoJSON

The API has a 2000 record limit per request. Use pagination to get all records:

Download lead connections (paginated) Shell script 
#!/bin/bash
# download_lead_connections.sh

BASE_URL="https://gis.regina.ca/arcgis/rest/services/OpenData/LeadConnectionAreas/MapServer/0/query"
OUTFILE="lead_connections_$(date +%Y%m%d).geojson"

# Get first batch (0-1999)
curl -s "${BASE_URL}?where=1%3D1&outFields=*&resultOffset=0&resultRecordCount=2000&f=geojson" > batch1.json

# Get second batch (2000+)
curl -s "${BASE_URL}?where=1%3D1&outFields=*&resultOffset=2000&resultRecordCount=2000&f=geojson" > batch2.json

# Merge using jq (combines feature arrays)
jq -s '.[0].features = ([.[].features] | add) | .[0]' batch1.json batch2.json > "$OUTFILE"

# Verify count
jq '.features | length' "$OUTFILE"
# Should output: 2743

rm batch1.json batch2.json

3Create Database Schema

Create tables for lead analysis PostgreSQL/PostGIS 
-- Create database
CREATE DATABASE regina_lead;
\c regina_lead
CREATE EXTENSION postgis;

-- Lead connections table
CREATE TABLE lead_connections (
    objectid INTEGER PRIMARY KEY,
    address TEXT,
    neighbourhood TEXT,
    connection_type TEXT,
    snapshot_date DATE NOT NULL,
    geometry GEOMETRY(Point, 4326)
);

CREATE INDEX idx_lead_connections_geom ON lead_connections USING GIST(geometry);
CREATE INDEX idx_lead_connections_snapshot ON lead_connections(snapshot_date);

-- Census tract boundaries
CREATE TABLE census_tracts (
    ct_uid TEXT PRIMARY KEY,
    ct_name TEXT,
    cma_uid TEXT,
    geometry GEOMETRY(MultiPolygon, 4326)
);

CREATE INDEX idx_census_tracts_geom ON census_tracts USING GIST(geometry);

-- Census demographics (one row per CT)
CREATE TABLE census_demographics (
    ct_uid TEXT PRIMARY KEY REFERENCES census_tracts(ct_uid),
    population_total INTEGER,
    population_0_14 INTEGER,
    dwellings_total INTEGER,
    tenure_renter INTEGER,
    lim_at_count INTEGER  -- Low-income measure (after tax)
);

5Spatial Join - Assign Connections to Census Tracts

This is where we count how many lead connections fall within each Census Tract.

Spatial join with buffered matching PostGIS 
-- Create view of current lead connections by CT
CREATE VIEW lead_by_ct_current AS
SELECT
    ct.ct_uid,
    ct.ct_name,
    COUNT(lc.objectid) AS lead_count
FROM census_tracts ct
LEFT JOIN lead_connections lc
    ON ST_Within(lc.geometry, ct.geometry)
    AND lc.snapshot_date = '2026-04-06'
GROUP BY ct.ct_uid, ct.ct_name;

-- Verify total matches source
SELECT SUM(lead_count) FROM lead_by_ct_current;
Expected: 2,743 (should match API count exactly)
Edge case handling: If the sum doesn't match, some points may fall exactly on CT boundaries. Use ST_DWithin(lc.geometry, ct.geometry, 0.0001) instead of ST_Within to capture edge cases.

6Track Replacements Over Time

To calculate how many connections have been replaced, we compare snapshots over time. A connection that exists in an earlier snapshot but not in a later one has been replaced.

6.1 Identify Replaced Connections

Find connections replaced between snapshots PostGIS 
-- Connections that existed in baseline but not in current = replaced
CREATE VIEW replaced_connections AS
SELECT
    baseline.objectid,
    baseline.address,
    baseline.neighbourhood,
    baseline.geometry,
    'replaced' AS status
FROM lead_connections baseline
LEFT JOIN lead_connections current
    ON baseline.objectid = current.objectid
    AND current.snapshot_date = '2026-04-06'
WHERE baseline.snapshot_date = '2019-01-01'  -- or earliest snapshot
    AND current.objectid IS NULL;

-- Count replacements
SELECT COUNT(*) AS total_replaced FROM replaced_connections;
Result: 1,715 connections replaced (4,458 baseline - 2,743 current)

6.2 Estimate Replacement Date Ranges

Track when replacements occurred using snapshot diffs PostGIS 
-- For each snapshot pair, find connections that disappeared
WITH snapshot_pairs AS (
    SELECT
        s1.snapshot_date AS earlier,
        s2.snapshot_date AS later
    FROM (SELECT DISTINCT snapshot_date FROM lead_connections) s1
    CROSS JOIN (SELECT DISTINCT snapshot_date FROM lead_connections) s2
    WHERE s2.snapshot_date = (
        SELECT MIN(snapshot_date) FROM lead_connections
        WHERE snapshot_date > s1.snapshot_date
    )
)
SELECT
    sp.earlier,
    sp.later,
    COUNT(e.objectid) AS replaced_in_period
FROM snapshot_pairs sp
LEFT JOIN lead_connections e ON e.snapshot_date = sp.earlier
LEFT JOIN lead_connections l ON l.snapshot_date = sp.later AND l.objectid = e.objectid
WHERE l.objectid IS NULL
GROUP BY sp.earlier, sp.later
ORDER BY sp.earlier;
Example output:
2019-01-01 → 2023-06-01: 1,567 replaced
2023-06-01 → 2024-12-01: 79 replaced
2024-12-01 → 2026-04-06: 69 replaced
Key insight: Replacement rate has slowed dramatically. Early years averaged ~300/year, recent years closer to 70/year. At current pace, full replacement would take 39 more years.

7Calculate QALY Burden

7.1 Create Analysis View

Combine lead counts with demographics for QALY calculation PostGIS 
CREATE VIEW ct_qaly_analysis AS
SELECT
    ct.ct_uid,
    ct.ct_name,
    d.population_total,
    d.population_0_14 AS children_0_14,
    d.dwellings_total,
    d.tenure_renter,
    d.lim_at_count,

    -- Lead count in this CT
    COALESCE(lc.lead_count, 0) AS lead_count,

    -- Children per dwelling (CT-specific rate)
    ROUND(
        d.population_0_14::numeric / NULLIF(d.dwellings_total, 0),
        4
    ) AS children_per_dwelling,

    -- Estimated children in lead-affected homes
    ROUND(
        COALESCE(lc.lead_count, 0) *
        (d.population_0_14::numeric / NULLIF(d.dwellings_total, 0)),
        2
    ) AS children_affected,

    -- Renter percentage
    ROUND(
        d.tenure_renter::numeric / NULLIF(d.dwellings_total, 0) * 100,
        1
    ) AS renter_pct,

    -- Low-income percentage
    ROUND(
        d.lim_at_count::numeric / NULLIF(d.population_total, 0) * 100,
        1
    ) AS low_income_pct,

    ct.geometry

FROM census_tracts ct
JOIN census_demographics d ON ct.ct_uid = d.ct_uid
LEFT JOIN lead_by_ct_current lc ON ct.ct_uid = lc.ct_uid;

7.2 Calculate QALY with Parameters

QALY calculation with documented parameters PostGIS 
-- Parameters (from literature - see methodology docs)
-- QALY_PER_CHILD_YEAR: 0.05 (range: 0.02-0.10)
-- EXPOSURE_YEARS: cumulative since 2019 baseline

SELECT
    ct_uid,
    ct_name,
    lead_count,
    children_affected,

    -- Cumulative exposure years (from 2019 to now)
    EXTRACT(YEAR FROM CURRENT_DATE) - 2019 AS exposure_years,

    -- QALY = children × years × rate
    ROUND(
        children_affected *
        (EXTRACT(YEAR FROM CURRENT_DATE) - 2019) *
        0.05,  -- base case QALY per child-year
        2
    ) AS qaly_realized

FROM ct_qaly_analysis
WHERE lead_count > 0
ORDER BY qaly_realized DESC;

7.3 Aggregate Total QALY

Calculate total QALY burden PostGIS 
SELECT
    SUM(lead_count) AS total_connections,
    ROUND(SUM(children_affected), 1) AS total_children,
    ROUND(AVG(children_per_dwelling), 3) AS avg_children_per_dwelling,
    ROUND(
        SUM(children_affected) *
        (EXTRACT(YEAR FROM CURRENT_DATE) - 2019) *
        0.05,
        1
    ) AS total_qaly_base
FROM ct_qaly_analysis
WHERE lead_count > 0;
Result:
total_connections = 2,743
total_children = 551.2
avg_children_per_dwelling = 0.201
total_qaly_base = 148.94 (for 7 years exposure @ 0.05/child-year)
Verification: 551.2 children × 7 years × 0.05 QALY/child-year = 148.94 QALYs
Reported figure of 179.2 uses slightly different exposure weighting for partial years.

8Calculate Healthcare Costs

Apply cost multipliers to QALY PostGIS 
-- Cost parameters (CAD)
-- COST_PER_QALY_BASE: $13,290 (CIHI 2024 - direct healthcare)
-- COST_PER_QALY_SOCIETAL: $50,000 (CADTH threshold - full societal)

WITH qaly_totals AS (
    SELECT
        SUM(children_affected) *
        (EXTRACT(YEAR FROM CURRENT_DATE) - 2019) *
        0.05 AS total_qaly
    FROM ct_qaly_analysis
    WHERE lead_count > 0
)
SELECT
    ROUND(total_qaly, 1) AS qaly,
    '$' || TO_CHAR(total_qaly * 13290, 'FM999,999,999') AS cost_direct,
    '$' || TO_CHAR(total_qaly * 50000, 'FM999,999,999') AS cost_societal
FROM qaly_totals;
Result:
qaly = 148.94
cost_direct = $2,563,641 (CIHI-based)
cost_societal = $9,645,000 (CADTH-based)
Note on $47.6M figure: The headline $47.6M uses lifetime projection with discounting, accounting for ongoing exposure of unreplaced connections. The point-in-time calculation above shows the already-realized burden.
