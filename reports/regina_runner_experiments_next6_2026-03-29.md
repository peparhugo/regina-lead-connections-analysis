# Regina runner experiments — next 6 (2026-03-29)

Status: canonical next-experiment plan
Purpose: define the next six Regina experiments to run through the unified Dream runner after validating stacks A/B, stabilizing C, and confirming the runner integration path.

---

## Executive design

These six experiments are designed to:
1. deepen the strongest current stacks (A/B),
2. determine whether C can become genuinely useful,
3. mature D into a real graph/recall hardening path,
4. generate Regina-specific reusable routing knowledge.

This is a targeted learning set, not an open-ended sweep.

---

# Experiment 1 — A-deepening: contradiction hotspot map

## Purpose
Map the highest-risk contradiction hotspots across the current support-layer and control-layer artifacts.

## Stack
- A (internal contradiction)

## Core questions
1. Which current support-layer artifacts most threaten canonical current-state answers if they are retrieved without boundary labeling?
2. Which exact contradictions or overclaim risks recur most across support, appendix, and package-adjacent artifacts?

## Expected value
- sharper contradiction hotspot map
- reusable demotion/non-promotion watchlist
- better Regina contradiction-control skill material

---

# Experiment 2 — B-deepening: preserve / promote / demote decision table

## Purpose
Turn the current operator-decision logic into a more explicit decision table for artifact handling.

## Stack
- B (internal decision support)

## Core questions
1. Which Regina artifacts are preserve-only, promote-candidate, demote-candidate, or historical-only right now?
2. What is the minimum evidence needed for a support artifact to become promotion-ready?

## Expected value
- operator-grade preservation/promote/demote table
- explicit promotion thresholds
- seed content for a Regina routing/decision skill

---

# Experiment 3 — C-split: WHO/CDC guidance path

## Purpose
Test the best current external support-communication route against high-trust public-health guidance sources only.

## Stack
- C (support communication comparison)

## Core questions
1. What public-health communication principles best support transparent communication under uncertainty without pseudo-precision?
2. What guidance patterns best separate technical detail from headline/public-facing claims?

## Route profile
- dedicated support-communication source profile
- institutional/public-health guidance emphasis only

## Expected value
- determine whether institutional guidance alone can make C genuinely useful
- improve source-specific route fit knowledge

---

# Experiment 4 — C-split: scholarly communication path

## Purpose
Test whether scholarly communication/risk-communication literature gives better usable signal than institutional guidance for Stack C.

## Stack
- C (support communication comparison)

## Core questions
1. What scholarly communication literature best supports communicating bounded/modelled estimates responsibly?
2. What research-backed patterns best avoid pseudo-precision while preserving public usefulness?

## Route profile
- scholarly-heavy support-communication route
- communication/risk/uncertainty framing emphasis

## Expected value
- compare institutional-guidance vs scholarly-literature performance inside C
- determine whether C should split into two subroutes permanently

---

# Experiment 5 — D-maturation: retrieval boundary probe set

## Purpose
Turn D into a more explicit boundary-hardening stack by probing the most dangerous query classes.

## Stack
- D (graph/recall boundary hardening)

## Core questions
1. Which current Regina query shapes most risk surfacing support-layer or historical artifacts above canonical current-state truth?
2. Which ranking/boundary interventions most reduce those risks without hiding useful support context?

## Expected value
- real retrieval-boundary probe set
- stronger D identity beyond generic internal validation
- direct input to graph/recall hardening rules

---

# Experiment 6 — cross-stack route comparison

## Purpose
Compare A/B/C/D against a single Regina objective so stack choice becomes evidence-based rather than intuitive.

## Shared objective
- improve safe communication and retrieval discipline for support-layer Regina material

## Comparison target
Run one aligned question/objective through:
- A contradiction framing
- B decision-support framing
- C communication-comparison framing
- D boundary-hardening framing

## Expected value
- best-stack-for-objective map
- stack selection evidence
- direct seed for a Regina lane selector / routing skill

---

## Recommended execution order
1. Experiment 1 (A-deepening)
2. Experiment 2 (B-deepening)
3. Experiment 5 (D-maturation)
4. Experiment 3 (C institutional guidance path)
5. Experiment 4 (C scholarly path)
6. Experiment 6 (cross-stack comparison)

Reason:
- deepen the strong internal backbone first;
- strengthen D before more external complexity;
- then split/evaluate C more carefully;
- finally compare stacks against one aligned objective.

---

## Why these six

These six experiments should answer the most important Regina runner questions now:
- what are the highest-risk contradiction hotspots?
- what is the preserve/promote/demote decision table?
- can C become genuinely useful, and through which source family?
- can D become a mature retrieval-boundary stack?
- which stack should be used for which Regina objective?

That is enough to improve both the project and the runner routing logic without exploding scope.
