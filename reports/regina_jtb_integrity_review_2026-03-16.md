## A) Executive verdict

### Overall verdict
**MIXED: PASS on documentary continuity / FAIL on package integrity / BLOCKED on full publication trust**

The current public/story package still preserves the core validated documentary spine:
- issue recognition is on record,
- 2021–2025 policy movement is documented,
- public/delegate pressure is present in the official process,
- and the strongest policy reading remains **incremental movement, not a true policy shift**.

But the package is **no longer fully aligned to the repo’s strongest JTB-validated state** in three ways:
1. the repo’s formally completed gate state is still centered on the earlier equity/documentary package, while the 2026-03-16 public package now leans harder on a broadened health-burden story;
2. several current public-facing artifacts speak more confidently about child-development / ADHD / adult chronic disease / healthy-life burden than the repo’s own completion state and publication gate actually validated;
3. publication status is internally inconsistent: some files say publish-ready / complete, while others say curation first, push second, and still others say push already happened.

## C) What drifted / is missing

### 1. Public package strength now exceeds the repo’s last clearly validated public gate
The repo’s mission state and Phase-3 publication gate were validated for the earlier equity/documentary package, with guardrails like non-causal framing and official-vs-inferred separation. See:
- `memory/mission-state.json`
- `reports/phase3_publication_gate_status_2026-03-10.md`
- `reports/final_synthesis_2026-03-06.md`

But the newer 2026-03-16 package adds a broader human-burden/public-health lane without an equivalent updated gate artifact showing full package validation.

**Integrity issue:** the repo treats “publication gate passed” and “project complete” as if they automatically transfer to the expanded package. They do not.

### 2. Homepage and bundle copy overextend the health lane relative to the strongest locked state
Examples:
- `index.html` says delay “affects families, children, and long-run health risk” and that “children bear the clearest long-run developmental risk.”
- `reports/regina_public_bundle_2026-03-16.html` says the research base supports a cautious child-development and long-run health framing including ADHD-type burden and increased later chronic disease risk.

Those statements may be directionally plausible within the literature review lane, but they are **not the same kind of claim** as the already JTB-locked documentary claims. The repo has literature notes and scenario sheets, but not a unified acceptance table showing which exact public-facing health claims are accepted, contested, or appendix-only.

### 3. Health-burden lane is internally cautious in technical docs, but more assertive in public packaging
The appendix docs are disciplined:
- `reports/regina_health_burden_technical_appendix_2026-03-16.md`
- `reports/regina_health_burden_public_table_2026-03-16.md`
- `reports/regina_healthy_life_burden_scenarios_2026-03-16.md`

These repeatedly say:
- appendix-only,
- no settled citywide total,
- proxy context only,
- no full QALY/DALY headline,
- no household-level verification,
- no direct Flint transfer.

But the public package often compresses that nuance into stronger narrative prose. The result is not outright fabrication, but **narrative compression that risks outrunning the actual caution layer**.

### 4. Publication-readiness state is contradictory across the repo
The following files conflict materially:
- `reports/regina_project_completion_checklist_2026-03-16.md` says the project is complete in publication-oriented mode.
- `reports/regina_prepublish_audit_and_curation_plan_2026-03-16.md` says the lane is **not yet safe to publish as-is** and requires curation first.
- `reports/regina_session_switch_summary_2026-03-16.md` says curation, commit split, and push already happened.

**Integrity issue:** the repo lacks one canonical source of truth for “what is publish-safe now.”

### 5. Claim-status management is missing for the 2026-03-16 package
There is a solid primary-source claim table for the documentary lane:
- `reports/regina_claim_evidence_table_primary_2026-03-12.md`

But there is no equivalent updated table for the full story package covering:
- homepage headline claims,
- journalist memo framing claims,
- bundle health-lane claims,
- appendix-only claims,
- needs-revalidation claims.

This is the biggest structural gap causing drift.

### 6. Delivery claims remain intentionally unverified, but some story copy edges toward implied practical harm without fresh implementation evidence
The tracker correctly says multiple 2025 directions are “DIRECTED_NOT_YET_VERIFIED.” See:
- `reports/regina_decision_to_delivery_tracker_2026-03-16.md`

That means the strongest narrative is still about **recognition, staged policy movement, and unresolved delivery adequacy**, not about demonstrated implementation failure. Some current wording gets close to implying more than the corpus currently proves.

## D) Strongest narrative we are actually entitled to

### Publication-safe core narrative
Regina had the lead-service-line problem on the formal agenda years ago. The official record shows real policy movement from 2021 through 2025, including baseline program adoption, later implementation changes, continued reporting direction, and additional affordability/outreach/reporting adjustments. Public/delegate pressure is visibly present in the official process. But the strongest current reading is still that the record shows **incremental movement rather than a true policy transformation**, and the current corpus does not yet prove that the adopted directions translated into fully delivered protection.

### What this narrative can safely include now
- formal recognition and continuity;
- documentary presence of public/delegate pressure;
- incremental-not-transformational scorecard result;
- open delivery/follow-through question;
- cautious statement that delay matters in human terms, **without making the health-burden lane do more than supporting-context work**.

### What it should not claim as settled yet
- that one delegation caused one later vote;
- that policy change already produced or failed to produce specific population-level health outcomes in Regina;
- that a citywide ADHD / cardiovascular / CKD / healthy-life burden has been sufficiently validated for headline use;
- that the appendix burden lane upgrades the documentary story into a quantified public-health conclusion.

## F) Recommended repair plan (ranked)

### 1) Create one canonical `current_claim_status` file for the entire 2026-03-16 package
**Priority: highest**

Add a single source of truth that lists every public-facing claim across:
- `index.html`
- `reports/regina_public_brief_plain_language_2026-03-12.md`
- `reports/regina_journalist_memo_2026-03-16.md`
- `reports/regina_public_handout_2026-03-16.md`
- `reports/regina_public_bundle_2026-03-16.html`

For each claim, mark:
- `ACCEPTED`
- `CONTESTED`
- `APPENDIX_ONLY`
- `NEEDS_REVALIDATION`

This is the missing anti-drift control.

### 2) Downgrade homepage and bundle health language to match the strongest already safe state
**Priority: very high**

Suggested rule:
- keep the homepage centered on documentary/process tension,
- keep human-impact language broad and cautious,
- move ADHD / adult chronic disease / healthy-life-years language one layer down into appendix/support docs unless revalidated line by line.

### 3) Re-run a package-level gate for the expanded 2026-03-16 public package
**Priority: very high**

The earlier gate passed for a narrower publication scope. Add a new package gate artifact specifically validating:
- homepage headline and subhead,
- brief + memo + handout consistency,
- bundle consistency,
- health-lane claims vs appendix limits,
- publication-readiness state.

### 4) Resolve publication-status contradictions
**Priority: high**

Pick one canonical state among:
- complete,
- curated but not yet publish-safe,
- pushed and live pending design refresh.

Then update or archive conflicting files:
- `reports/regina_project_completion_checklist_2026-03-16.md`
- `reports/regina_prepublish_audit_and_curation_plan_2026-03-16.md`
- `reports/regina_session_switch_summary_2026-03-16.md`

### 5) Keep decision-to-delivery wording disciplined
**Priority: high**

Preserve the tracker’s logic in all public docs:
- adopted directions are real,
- follow-through remains the next verification layer,
- do not imply measured implementation failure where the corpus only shows directed-but-not-yet-verified action.

### 6) Keep the appendix as appendix
**Priority: medium-high**

Maintain explicit separation:
- documentary headline claim,
- support-layer health framing,
- appendix-only numeric burden work.

The appendix is useful; letting it leak upward as a narrative crutch is the drift risk.

---

## Bottom line

The current Regina package still contains a strong and defensible core story. The problem is **not** that the repo lost its documentary spine. The problem is that the public package has grown faster than the project’s claim-control layer.

**Safe to publish now:**
- recognition → staged policy movement → incremental-not-transformational verdict → open delivery question.

**Not yet safe to fully trust without repair:**
- the whole package as one unified JTB-locked public-health/accountability narrative.

The repair is straightforward: re-anchor the expanded package to a single current claim-status ledger, then trim the public-facing health language until it matches the strongest actually validated state.
